# Битрикс24 как канал Авы — Design

**Дата:** 2026-08-06
**Статус:** утверждено владельцем в ходе брейнсторма
**Связано:** Ава развёрнута на своём VPS (`83.222.26.241`, служба `ava`), см. `deploy/`

---

## 1. Цель

Сотрудники портала Битрикс24 пишут Аве и получают ответ прямо в портале — так же
естественно, как сейчас в Telegram. У Авы в портале три роли, разные по правам:

- **разговор «для души»** — её характер, поддержка, тексты, объяснения;
- **знание системы «Идеальные стены»** — она разбирается в продукте, объясняет
  его человеку и сама поддерживает базу знаний в актуальном виде;
- **личный помощник собственника** — отдельный, изолированный контур.

Чего Ава НЕ делает ни для кого: не отвечает на вопросы про цифры учёта. Это зона
Игоря (проект «Агент»), данных 1С у Авы нет и не будет.

## 2. Роли

| Роль | Кто | Что доступно |
|---|---|---|
| Собственник | Дмитрий Цыплаков (ID 1) | Личный контур: своя память, без потолка расхода, личный помощник. Память закрыта от ВСЕХ остальных |
| Управляющий доступами | Елена (ID 6) | Списки профилей, согласование правок базы знаний, аналитика качества (без содержания личных диалогов) |
| Начальник отдела маркетинга | по списку | Приносит информацию о продукте, согласует правки, получает отчёт о работе с базой |
| Специалисты маркетинга | по списку | Предлагают правки. Вносятся ТОЛЬКО после согласования |
| Сотрудники портала | все активные | Разговор и вопросы по продукту. Действуют лимиты. Голос и видео — только если есть в списке |

Умолчание для любого списка — **запрет**: кого в списке нет, тот получает базовый
текстовый режим.

## 3. Контуры памяти

Три РАЗДЕЛЬНЫХ хранилища. Разделение физическое, а не фильтром на выходе.

| Контур | Что внутри | Кто читает | Кто пишет |
|---|---|---|---|
| Личный контур собственника | Его дела, поездки, напоминания, личные договорённости | Только он, в своём диалоге | Он и Ава в его диалоге |
| База знаний по продукту | «Идеальные стены»: материалы маркетинга | Все сотрудники | Только по согласованию (§6) |
| Память диалога | Ход текущего разговора | Участник этого диалога | Ава |

**Главное правило изоляции.** При ответе кому угодно, кроме собственника, личный
контур **не подключается к поиску вовсе**. Это не «нашли и вычеркнули», а «не
искали»: то, что не попало в контекст, не может утечь ни при каких уговорах.
Закрыто тестом, который проверяет отсутствие обращения к хранилищу, а не
отсутствие слов в ответе.

## 4. Архитектура

```
┌─ Битрикс24 (облако) ────────────────────────────────────────┐
│  Локальное приложение портала + чат-бот (imbot)             │
│  событие ONIMBOTMESSAGEADD                                  │
└───────────────────────┬─────────────────────────────────────┘
                        │ HTTPS POST
┌───────────────────────▼─────────────────────────────────────┐
│  nginx на сервере Авы (83.222.26.241.sslip.io)              │
│    :443  /bitrix/  → 127.0.0.1:3777                         │
│    :443  /health   → 127.0.0.1:3777                         │
│    :443  всё прочее → 404   (панель наружу НЕ выставляем)   │
│    :80   только ACME-челлендж + редирект на https           │
└───────────────────────┬─────────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────────┐
│  src/channels/bitrix/   — ТОЛЬКО транспорт                  │
│    handler.ts   приём события, проверка подлинности, 200    │
│    queue.ts     очередь: ответ считается асинхронно         │
│    client.ts    REST поверх вебхука (отправка, обрезка)     │
└───────────────────────┬─────────────────────────────────────┘
                        │ ChannelRequest {текст, кто, диалог, канал}
┌───────────────────────▼─────────────────────────────────────┐
│  src/core/  — ЯДРО, здесь вся логика                        │
│    engine.ts            агентный цикл (уже есть)            │
│    profiles.ts          кто есть кто, режимы, голос/видео   │
│    tools/bitrix.ts      умения портала                      │
│    memory/product/      база знаний по продукту             │
│    memory/personal/     личный контур собственника          │
│    policy/bitrix.ts     правила поведения и изоляции        │
└─────────────────────────────────────────────────────────────┘
```

Зависимость строго в одну сторону: канал знает про ядро, ядро про канал — нет.
Ядро при этом полноценно «знает Битрикс» — через инструмент и контекст запроса,
а не через импорт транспорта. Иначе ядро нельзя протестировать без поднятого
HTTP, что запрещено правилами проекта (`CLAUDE.md`).

## 5. Профили пользователей

`profiles.ts` отвечает на один вопрос: кто написал и что ему положено.

| Признак | Значение |
|---|---|
| Роль | Из §2, по ID сотрудника портала |
| Режим общения | Свой для отдельных людей: тон, обращение, глубина ответов. Остальным — общий |
| Голос | Только тем, кто в списке |
| Видео-кружочки | Только тем, кто в списке |
| Лимиты | Собственнику — нет. Остальным: 15 вопросов в час, 300 в сутки на портал, суточный потолок расхода |

Списки ведёт Елена и передаёт их составом; хранятся в конфиге, меняются без
пересборки.

## 6. База знаний по продукту

Отдельное хранилище (`memory/product/`), не смешанное ни с личным контуром, ни с
памятью диалогов.

**Кто может менять:**

| Кто | Как |
|---|---|
| Собственник | Правка вносится сразу |
| Елена | Правка вносится сразу |
| Начальник отдела маркетинга | Правка вносится сразу |
| Специалисты маркетинга | Только после подтверждения: «Ольга просит внести эти изменения, вы согласны?» Подтверждает Елена или начальник отдела |
| Все прочие | Запрещено. Вежливый отказ |

**Как Ава работает с базой.** Принимает от маркетинга новые материалы, сама
находит, что устарело или противоречит новому, предлагает правку и после
согласования вносит. Каждое изменение попадает в журнал: кто предложил, кто
согласовал, что изменилось, когда.

**Отчёт начальнику отдела маркетинга** — периодический: какие изменения внесены,
по чьей рекомендации, и — отдельным разделом — **чего в базе не хватило**: вопросы
сотрудников, на которые она не нашла ответа. Это самая ценная часть отчёта: она
показывает дыры в материалах.

## 7. Личный контур собственника

Включается только в его диалоге, по его ID.

- **Своя память** — дела, поездки, напоминания, договорённости. Не участвует в
  ответах никому другому (§3).
- **Без потолка расхода.** Лимиты частоты к нему не применяются.
- **Личный помощник:** поиск выгодных билетов, бронирование от его имени,
  напоминания.

**Бронирование требует явного подтверждения.** Ава ищет, сравнивает и предлагает;
покупка или бронь совершается только после его «да» на конкретный вариант с
названной ценой. Автономных покупок нет — это деньги и обязательства, а модель
может ошибиться в дате или городе.

## 8. Аналитика для Елены

Цель — настраивать Аву под задачи собственника, не читая его переписку.

**Уходит:** категории вопросов, доля неудачных ответов, случаи «не нашла в базе»,
случаи переспроса, использованные инструменты, время ответа, расход, замечания по
поведению («дважды предложила бронь без подтверждения»).

**Не уходит:** содержание личных диалогов и личной памяти собственника.

Если для разбора нужен конкретный фрагмент — он запрашивается у собственника и
передаётся только после его явного согласия.

## 9. Компоненты

### 9.1 Канал `src/channels/bitrix/`

**`handler.ts`** — принимает POST от Битрикса.

1. Проверяет подлинность: `application_token` события совпадает с сохранённым.
   Не совпал или пуст → `401`, запись в журнал. **Пустой токен НЕ отключает
   проверку** — на этих граблях проект «Агент» уже стоял.
2. Отвечает `200` немедленно. Битрикс не ждёт: долгий ответ = повторные события.
3. Кладёт задание в очередь.

**`queue.ts`** — последовательная обработка на диалог. Пока Ава думает над
вопросом из чата, следующий вопрос из того же чата ждёт: иначе два ответа
перепутаются местами.

**`client.ts`** — вызовы REST через входящий вебхук. Отвечает за обрезку до 8000
символов (сохраняя начало и конец) и за то, что URL вебхука не покидает модуль.

### 9.2 Умения в ядре `src/core/tools/bitrix.ts`

Обычный `Tool` в реестре. Модель сама решает, когда им воспользоваться.

| Операция | Назначение |
|---|---|
| `send_message` | Написать в диалог портала |
| `find_user` | Найти сотрудника по имени, узнать отдел и должность |
| `list_department` | Состав отдела — чтобы понимать, кто спрашивает |

Инструмент получает вебхук из конфига при создании. В описании инструмента и в
его параметрах секрета нет — модель оперирует смыслом, не адресом.

### 9.3 Правила поведения `src/core/policy/bitrix.ts`

Отдельный модуль, потому что это знание бизнеса, а не транспорт, и оно должно
быть закрыто тестами независимо от HTTP.

- **Цифры учёта → к Игорю.** Распознавание в два слоя, потому что одного мало:
  1. *Промпт.* Правило записано в системную инструкцию канала.
  2. *Страховка на выходе.* Готовый ответ проверяется: если в нём есть денежная
     сумма (число с разделителями разрядов, «руб», «₽»), а вопрос отнесён к
     учётным, ответ ЗАМЕНЯЕТСЯ отказом. Промпт можно обойти уговорами, проверку
     на выходе — нет. Именно она закрыта регрессионным тестом.
- **Продукт → объясняем.** Материалы ищутся полнотекстовым поиском по базе знаний
  (`minisearch`, уже используется в `src/core/memory/`) по тексту вопроса.
  Найденные куски кладутся в контекст и остаются там на весь разговор, чтобы
  допвопросы не теряли почву. Ответ — своими словами, под собеседника.
- **Точные числа — со ссылкой.** Цена, размер, срок звучат только если найдены в
  документах, и рядом указывается источник.
- **Не знаем — говорим.** Отсутствие в документах не заполняется догадкой.
- **Изоляция личного контура** (§3) — проверяется до сборки контекста.

## 10. Поток данных

```
сотрудник пишет в портале
   → Битрикс шлёт событие на /bitrix/
   → подлинность? нет → 401
   → 200 сразу, задание в очередь
   → профиль: кто это, роль, режим, голос/видео, лимиты
   → лимит исчерпан? → вежливый отказ
   → сборка контекста: продукт + память диалога
        личный контур подключается ТОЛЬКО если это собственник
   → правила: вопрос про учёт? → отказ + к Игорю
   → агентный цикл (модель + инструменты)
   → страховка на выходе → обрезка до 8000 → ответ в ТОТ ЖЕ диалог
```

Ответ всегда уходит туда, откуда пришёл вопрос. Адресат — часть задания, а не
настройка: на этом проект «Агент» уже обжигался.

## 11. Безопасность

- Событие обязано быть подтверждено токеном приложения. Умолчание — отказ.
- Вебхук и токен — в `~/.betsy/config.yaml` (права 600, владелец `ava`).
- Наружу открыты только `/bitrix/` и `/health`. Панель управления (3777)
  остаётся закрытой: пароль по открытому HTTP наружу ходить не должен.
- Личный контур собственника недоступен никому, включая Елену (§3, §8).
- Правки базы знаний — только от разрешённых ролей, остальным отказ (§6).
- Лимиты частоты защищают и от перерасхода, и от случайного цикла «бот отвечает
  боту»: сообщения от ботов игнорируются по признаку отправителя.
- Ава ничего не пишет в 1С и не имеет к ней доступа — по построению.

## 12. Ошибки и отказы

| Что случилось | Поведение |
|---|---|
| Битрикс недоступен при отправке | Три попытки с нарастающей паузой, потом запись в журнал. Вопрос не теряется |
| Модель не ответила | Сотруднику — человеческое «не смогла ответить, попробуйте позже», подробность в журнал |
| Событие не прошло проверку | `401`, запись в журнал с IP. Ответа в портал нет |
| Превышен лимит | Вежливый отказ с указанием, когда можно снова |
| Суточный потолок расхода | Ава отвечает, что на сегодня лимит исчерпан; Елене — уведомление. К собственнику не применяется |
| Правка базы знаний без прав | Вежливый отказ, запись в журнал |

Ошибки не глушим: каждая уходит в журнал службы (`journalctl -u ava`).

## 13. Инфраструктура

На сервере Авы, повторяя проверенную у Игоря схему:

1. `nginx` + `certbot`, сертификат Let's Encrypt на `83.222.26.241.sslip.io`.
2. `ufw`: открыть 80 (только ACME и редирект) и 443. Порт 22 уже открыт.
3. Публичный `server`-блок включается ТОЛЬКО после выпуска сертификата — иначе
   `nginx -t` падает на отсутствующих файлах (грабли из проекта «Агент»).
4. Служба `ava` не меняется: как слушала 3777 на localhost, так и слушает.

## 14. Тестирование

Модульные (без сети и HTTP):

- подделка события → `401`; пустой токен → `401`, а не «проверка отключена»;
- вопрос про кассу/долги → ответ без единой суммы и с упоминанием Игоря;
- страховка на выходе: подсунутый ответ с суммой на учётный вопрос заменяется
  отказом (проверяется внедрением регрессии, а не только «зелёным» случаем);
- **изоляция личного контура: при запросе от любого не-собственника к личному
  хранилищу НЕ происходит обращения** — проверяется на уровне вызова, а не по
  тексту ответа;
- голос и видео не выдаются тому, кого нет в списке;
- правка базы знаний от специалиста без согласования не применяется;
- лимит частоты срабатывает на 16-м вопросе в час, к собственнику не применяется;
- обрезка длинного текста сохраняет начало и конец;
- сообщение от бота игнорируется.

Интеграционные: поддельный сервер Битрикса, полный путь «событие → ответ»,
включая порядок ответов в одном диалоге.

Живая проверка (условие сдачи): сотрудник спрашивает про «Идеальные стены»,
получает внятное объяснение, задаёт допвопрос и получает ответ, продолжающий
разговор. Отдельно: вопрос про кассу → отказ и Игорь.

## 15. Этапы

Порядок не произвольный: личный контур обязан появиться РАНЬШЕ личного помощника,
иначе помощник начнёт складывать личные данные в общую память, и вынуть их оттуда
будет нечем.

| Этап | Содержание | Условие сдачи |
|---|---|---|
| 1 | Канал Битрикса + профили пользователей, режимы, голос и видео по спискам | Сотрудник получает ответ в портале; не из списка — без голоса |
| 2 | База знаний по продукту, согласование правок, отчёт маркетингу | Правка от специалиста проходит только после согласования; отчёт приходит |
| 3 | Личный контур собственника: память, отсутствие лимитов, изоляция | Тест изоляции зелёный; в чужом чате личное не всплывает |
| 4 | Личный помощник: билеты, бронирования, напоминания | Бронь совершается только после явного подтверждения |

Каждый этап получает свой план реализации.

## 16. Что НЕ входит

- Создание задач, сделок, дел в портале. Это запись в чужую систему и отдельное
  решение владельца.
- Права по отделам для данных, как у Игоря: чувствительных данных у Авы нет,
  разграничивать нечего. Разграничение идёт по ролям (§2), а не по отделам.
- Ответы в открытых групповых чатах по упоминанию — только личные диалоги с
  ботом, чтобы не шуметь в рабочих обсуждениях.
- Доступ Авы к 1С в любом виде.

## 17. Что нужно от владельца

1. **Локальное приложение в портале** с правами на чат и пользователей, адрес
   обработчика событий — `https://83.222.26.241.sslip.io/bitrix/`.
2. **Входящий вебхук** портала для отправки сообщений.
3. **Списки:** кому голос, кому видео, кому особый режим общения; ID начальника
   отдела маркетинга и его специалистов.
4. **Документы по «Идеальным стенам»** — сложить в папку, я загружу в базу.
5. **Потолок расхода в сутки** для сотрудников (на собственника не действует).
6. **Периодичность отчёта** начальнику отдела маркетинга.
