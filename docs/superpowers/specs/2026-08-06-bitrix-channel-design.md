# Битрикс24 как канал Авы — Design

**Дата:** 2026-08-06
**Статус:** утверждено владельцем в ходе брейнсторма
**Связано:** Ава развёрнута на своём VPS (`83.222.26.241`, служба `ava`), см. `deploy/`

---

## 1. Цель

Сотрудники портала Битрикс24 пишут Аве и получают ответ прямо в портале — так же
естественно, как сейчас в Telegram. Ава в портале отвечает за две вещи:

- **разговор «для души»** — её характер, поддержка, тексты, объяснения;
- **знание системы «Идеальные стены»** — она разбирается в продукте и умеет
  объяснить его человеку.

Чего Ава в портале НЕ делает: не отвечает на вопросы про цифры учёта. Это зона
Игоря (проект «Агент»), у Авы данных 1С нет и не будет.

## 2. Зафиксированные решения

| Решение | Значение |
|---|---|
| Кому отвечает | Всем сотрудникам портала (46 активных), как Игорь |
| Граница с Игорем | Цифры учёта → честный отказ и переадресация к Игорю. Закрыто регрессионным тестом |
| Знание продукта | Объясняет своими словами и ведёт беседу, а не выдаёт цитаты из документов |
| Источник знания | Документы владельца, загруженные в базу знаний Авы |
| Ссылка на источник | По требованию («откуда это?») и ОБЯЗАТЕЛЬНО там, где цена, размер или срок |
| Чего нет в документах | Прямое «не знаю», предложение уточнить у человека. Сочинительство запрещено |
| Память диалога | По каждому чату портала: допвопросы продолжают разговор, а не начинают с нуля |
| Умения Битрикса | Инструмент В ЯДРЕ (`src/core/tools/bitrix.ts`), рядом с `http`, `ssh`, `selfie` |
| Канал | `src/channels/bitrix/` — только транспорт: приём события, подлинность, очередь |
| Публичный адрес | `83.222.26.241.sslip.io` + Let's Encrypt, на СВОЁМ сервере Авы |
| Почему не сервер Игоря | Изоляция ботов: общий nginx = общая точка отказа и чужой репозиторий |
| Секрет вебхука | Только в конфиге. В контекст модели не попадает никогда |
| Длина сообщения | Режем до 8000 символов (Битрикс режет сам — опыт Игоря) |
| Лимиты | 15 вопросов в час на сотрудника, 300 в сутки на портал, суточный потолок расхода |

## 3. Архитектура

```
┌─ Битрикс24 (облако) ────────────────────────────────────────┐
│  Локальное приложение портала + чат-бот (imbot)             │
│  событие ONIMBOTMESSAGEADD                                  │
└───────────────────────┬─────────────────────────────────────┘
                        │ HTTPS POST
┌───────────────────────▼─────────────────────────────────────┐
│  nginx на сервере Авы (83.222.26.241.sslip.io)              │
│    :443  /bitrix/  → 127.0.0.1:3777                         │
│    :443  /health   → 127.0.0.1:3777                         │
│    :443  всё прочее → 404   (панель наружу НЕ выставляем)   │
│    :80   только ACME-челлендж + редирект на https           │
└───────────────────────┬─────────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────────┐
│  src/channels/bitrix/   — ТОЛЬКО транспорт                  │
│    handler.ts   приём события, проверка подлинности, 200    │
│    queue.ts     очередь: ответ считается асинхронно         │
│    client.ts    REST поверх вебхука (отправка, обрезка)     │
└───────────────────────┬─────────────────────────────────────┘
                        │ ChannelRequest {текст, кто, диалог, канал}
┌───────────────────────▼─────────────────────────────────────┐
│  src/core/  — ЯДРО, здесь вся логика                        │
│    engine.ts          агентный цикл (уже есть)              │
│    tools/bitrix.ts    умения портала (НОВОЕ)                │
│    memory/            база знаний + память диалога          │
│    policy/bitrix.ts   правила поведения (НОВОЕ)             │
└─────────────────────────────────────────────────────────────┘
```

Зависимость строго в одну сторону: канал знает про ядро, ядро про канал — нет.
Ядро при этом полноценно «знает Битрикс» — через инструмент и контекст запроса,
а не через импорт транспорта. Иначе ядро нельзя протестировать без поднятого
HTTP, что запрещено правилами проекта (`CLAUDE.md`).

## 4. Компоненты

### 4.1 Канал `src/channels/bitrix/`

**`handler.ts`** — принимает POST от Битрикса.

1. Проверяет подлинность: `application_token` события совпадает с сохранённым.
   Не совпал или пуст → `401`, запись в журнал. **Пустой токен НЕ отключает
   проверку** — на этих граблях проект «Агент» уже стоял.
2. Отвечает `200` немедленно. Битрикс не ждёт: долгий ответ = повторные события.
3. Кладёт задание в очередь.

**`queue.ts`** — последовательная обработка на диалог. Пока Ава думает над
вопросом из чата, следующий вопрос из того же чата ждёт: иначе два ответа
перепутаются местами.

**`client.ts`** — вызовы REST через входящий вебхук. Отвечает за обрезку до 8000
символов (сохраняя начало и конец) и за то, что URL вебхука не покидает модуль.

### 4.2 Умения в ядре `src/core/tools/bitrix.ts`

Обычный `Tool` в реестре. Модель сама решает, когда им воспользоваться.

| Операция | Назначение |
|---|---|
| `send_message` | Написать в диалог портала |
| `find_user` | Найти сотрудника по имени, узнать отдел и должность |
| `list_department` | Состав отдела — чтобы понимать, кто спрашивает |

Инструмент получает вебхук из конфига при создании. В описании инструмента и в
его параметрах секрета нет — модель оперирует смыслом, не адресом.

### 4.3 Правила поведения `src/core/policy/bitrix.ts`

Отдельный модуль, потому что это знание бизнеса, а не транспорт, и оно должно
быть закрыто тестами независимо от HTTP.

- **Цифры учёта → к Игорю.** Распознавание в два слоя, потому что одного мало:
  1. *Промпт.* Правило записано в системную инструкцию канала: данных 1С нет,
     такие вопросы — к Игорю.
  2. *Страховка на выходе.* Готовый ответ проверяется: если в нём есть денежная
     сумма (число с разделителями разрядов, «руб», «₽»), а вопрос отнесён к
     учётным, ответ ЗАМЕНЯЕТСЯ отказом. Промпт можно обойти уговорами, проверку
     на выходе — нет. Именно она закрыта регрессионным тестом.
- **Продукт → объясняем.** Материалы по «Идеальным стенам» ищутся полнотекстовым
  поиском по базе знаний (`minisearch`, уже используется в `src/core/memory/`) по
  тексту вопроса. Найденные куски кладутся в контекст и остаются там на весь
  разговор, чтобы допвопросы не теряли почву. Ответ — своими словами, под
  собеседника.
- **Точные числа — со ссылкой.** Цена, размер, срок звучат только если найдены в
  документах, и рядом указывается источник.
- **Не знаем — говорим.** Отсутствие в документах не заполняется догадкой.

### 4.4 Знание продукта

Документы владельца загружаются в базу знаний Авы (SQLite + поиск, уже есть в
`src/core/memory/`). Загрузка — разовая операция скриптом, повторный запуск
обновляет содержимое, не плодя дубли.

## 5. Поток данных

```
сотрудник пишет в портале
   → Битрикс шлёт событие на /bitrix/
   → подлинность? нет → 401
   → 200 сразу, задание в очередь
   → ядро: контекст (кто, отдел, диалог, канал=bitrix)
   → правила: вопрос про учёт? → отказ + к Игорю → отправка
   → иначе: подбор материалов по продукту + память диалога
   → агентный цикл (модель + инструменты)
   → обрезка до 8000 → отправка в ТОТ ЖЕ диалог
```

Ответ всегда уходит туда, откуда пришёл вопрос. Адресат — часть задания, а не
настройка: на этом проект «Агент» уже обжигался.

## 6. Безопасность

- Событие обязано быть подтверждено токеном приложения. Умолчание — отказ.
- Вебхук и токен — в `~/.betsy/config.yaml` (права 600, владелец `ava`).
- Наружу открыты только `/bitrix/` и `/health`. Панель управления (3777)
  остаётся закрытой: пароль по открытому HTTP наружу ходить не должен.
- Лимиты частоты защищают и от перерасхода, и от случайного цикла «бот отвечает
  боту»: сообщения от ботов игнорируются по признаку отправителя.
- Ава ничего не пишет в 1С и не имеет к ней доступа — по построению.

## 7. Ошибки и отказы

| Что случилось | Поведение |
|---|---|
| Битрикс недоступен при отправке | Три попытки с нарастающей паузой, потом запись в журнал. Вопрос не теряется |
| Модель не ответила | Сотруднику — человеческое «не смогла ответить, попробуйте позже», подробность в журнал |
| Событие не прошло проверку | `401`, запись в журнал с IP. Ответа в портал нет |
| Превышен лимит | Вежливый отказ с указанием, когда можно снова |
| Суточный потолок расхода | Ава отвечает, что на сегодня лимит исчерпан; владельцу — уведомление |

Ошибки не глушим: каждая уходит в журнал службы (`journalctl -u ava`).

## 8. Инфраструктура

На сервере Авы, повторяя проверенную у Игоря схему:

1. `nginx` + `certbot`, сертификат Let's Encrypt на `83.222.26.241.sslip.io`.
2. `ufw`: открыть 80 (только ACME и редирект) и 443. Порт 22 уже открыт.
3. Публичный `server`-блок включается ТОЛЬКО после выпуска сертификата — иначе
   `nginx -t` падает на отсутствующих файлах (грабли из проекта «Агент»).
4. Служба `ava` не меняется: как слушала 3777 на localhost, так и слушает.

## 9. Тестирование

Модульные (без сети и HTTP):

- подделка события → `401`; пустой токен → `401`, а не «проверка отключена»;
- вопрос про кассу/долги → ответ без единой суммы и с упоминанием Игоря;
- страховка на выходе: подсунутый ответ с суммой на учётный вопрос заменяется
  отказом (проверяется внедрением регрессии, а не только «зелёным» случаем);
- обрезка длинного текста сохраняет начало и конец;
- лимит частоты срабатывает на 16-м вопросе в час;
- сообщение от бота игнорируется.

Интеграционные: поддельный сервер Битрикса, полный путь «событие → ответ»,
включая порядок ответов в одном диалоге.

Живая проверка (условие сдачи): сотрудник пишет Аве в портале вопрос про
«Идеальные стены», получает внятное объяснение, задаёт допвопрос и получает
ответ, продолжающий разговор. Отдельно: вопрос про кассу → отказ и Игорь.

## 10. Что НЕ входит

- Создание задач, сделок, дел в портале. Это запись в чужую систему и отдельное
  решение владельца — этап 2.
- Голос и видео-кружочки в Битриксе: канал текстовый.
- Права по отделам, как у Игоря. Ава отвечает всем одинаково — у неё нет
  чувствительных данных, разграничивать нечего.
- Ответы в открытых групповых чатах по упоминанию — только личные диалоги с
  ботом, чтобы не шуметь в рабочих обсуждениях.

## 11. Что нужно от владельца

1. **Локальное приложение в портале** с правами на чат и пользователей, адрес
   обработчика событий — `https://83.222.26.241.sslip.io/bitrix/`.
2. **Входящий вебхук** портала для отправки сообщений.
3. **Документы по «Идеальным стенам»** — сложить в папку, я загружу в память.
4. **Потолок расхода в сутки** — сумма, после которой Ава останавливается.
